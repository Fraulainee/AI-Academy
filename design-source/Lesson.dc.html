Why attention replaced recurrence

The bottleneck in recurrent networks

A recurrent network reads a sentence one token at a time and folds everything it has read into a single {{tm.hidden.name}}{{tm.hidden.def}} of fixed size.

Whatever the network knows about the first word must survive every later update to that state. In practice it does not survive intact: by the end of a long sentence, the opening words leave only a faint trace, and the model struggles to connect a pronoun to the noun it refers to several words earlier.2

Every token consults every other token

Attention removes this bottleneck. Instead of relaying information step by step, every token consults every other token directly and decides how much each one should contribute to its own representation.

To do so, each token is projected into three vectors: a {{tm.query.name}}{{tm.query.def}}, a {{tm.key.name}}{{tm.key.def}} and a {{tm.value.name}}{{tm.value.def}}. Then:

  1. One token's query is compared with the key of every token in the sentence.
  2. The comparison scores are converted into weights by a {{tm.softmax.name}}{{tm.softmax.def}}.
  3. The token's new representation is the weighted average of all the values.13

Explore the figures

Three interactive figures. Figures 1 and 2 share one selection.

A Transformer learns many {{tm.head.name}}{{tm.head.def}} side by side, each with its own pattern of weights. Figure 1 shows two of them for a single sentence.

Drawn for every word at once, the same weights form a square matrix. Row i holds the weights that token i assigns to each token in the sentence, so every row sums to one.

Where do the weights come from? Scaled dot-product attention computes them in four steps.1 Figure 3 runs them on the Laboratory 3 example: one query, three keys and three values, each with two components, so dk = 2. The scores are divided by {{tm.scale.name}}{{tm.scale.def}} before the softmax.

Soft weights and parallel computation

Two consequences follow from Figure 3. First, the output is a soft mixture: every value contributes in proportion to its weight, so the whole computation can be differentiated and trained by gradient descent. {{tm.hardsoft.name}}{{tm.hardsoft.def}} would instead select only the highest-scoring key, an operation with no useful gradient.

Second, no step depends on the result for the previous token, so the computation for every token in a sentence can run at once. That parallelism, rather than any single accuracy gain, is what allowed the Transformer to replace recurrent models in practice.1

Key takeaway

Attention replaces the fixed-size hidden state of a recurrent network with direct, weighted connections between every pair of tokens. Each weight comes from comparing a query with a key, scaling by √dk and applying softmax, and the output is the weighted average of the values. Because that mixture is soft and no token waits for the one before it, attention can be trained by gradient descent and computed in parallel.

Laboratory 3: Scaled dot-product attention

Part 1Not startedDue 17 October 2026, 11:59 PM PHT10% of final grade

Compute the attention output by hand, then implement and verify it in PyTorch.

What to do

  1. Set up. Open the Laboratory 3 notebook from the course workspace; the required libraries are pre-installed. Select the device with device = "cuda" if torch.cuda.is_available() else "cpu".
  2. Part A: Concepts. In a short written answer, explain why soft attention can be trained by gradient descent and hard attention cannot.
  3. Part B: By hand, then in code. Using the query, keys and values in Figure 3, compute the scores, apply softmax and form the weighted sum. Confirm each intermediate result in PyTorch.
  4. Part C: Experiments.
    • Scaling ablation: remove the √dk term, increase dk to 64, and report how the weights change.
    • Hard and soft attention: compare argmax selection with the softmax blend on the same inputs.
attention_lab.pyPython 3 · PyTorch
# Laboratory 3, Part 1: scaled dot-product attention
import torch, torch.nn.functional as F

q = torch.tensor([[1., 0.]])                       # 1 query
K = torch.tensor([[1., 0.], [0., 1.], [1., 1.]])   # 3 keys
V = torch.tensor([[1., 0.], [0., 1.], [2., 2.]])   # 3 values

scores = q @ K.T / (2 ** 0.5)
w = F.softmax(scores, dim=-1)
out = w @ V
print(scores, w, out)

# reusable version for Part C
def scaled_dot_product_attention(query, key, value):
    d_k = query.shape[-1]
    scores = torch.matmul(query, key.transpose(-2, -1)) / (d_k ** 0.5)
    weights = F.softmax(scores, dim=-1)
    return torch.matmul(weights, value), weights
